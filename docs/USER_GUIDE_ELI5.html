Clash 节点测速助手：30 秒看懂它是干嘛的

平时找节点就像逛菜市场挑西瓜，光看名字（“高速/低延迟”）根本不知道哪个真甜。 这个助手就像帮你请了个“跑腿试吃员”：你不用自己一个个切节点打开网页试，它会同时派出几个小分队，拿着小本子去 Cloudflare 真实下载一小块文件，测完直接给你排出 0–100 分的红黑榜。

核心原则：只读你本机 Clash Verge 的订阅，绝不篡改软件本身；你不点开始，它一丁点流量都不会跑。

✧ 一句话记住它的脾气
先用“真实下载”排榜
再按“你的允许”切换
  • 不是测个 Ping 值就完事：它会算速度 + 延迟 + 失败率 + 抖动。
  • 不会偷偷切节点：自动切换默认关闭。
  • 不是免费白嫖测速：真实下载会扣你的节点流量。
适用：Windows x64 多订阅工作台 / macOS 版

✅ 它能帮你省哪些事？

  • 把多个订阅里的几百上千个节点放进一张表里同台 PK。
  • 用 “智能两段优选” 先小流量海选、再大流量复测前几名，省钱又省时间。
  • 觉得哪个最稳，一键切到你指定的 Clash 策略组里（切错了还能点 切回原节点）。

⚠️ 它故意不替你做什么？

  • 不碰陌生订阅黑盒：只认规范的内联 proxies，带复杂 proxy-providers 的会直接拒测，防踩坑。
  • 不当流量保镖：预计流量只是下载正文估算，实际扣费可能更高，按量计费套餐请悠着点测。
  • 不做无声自动后台：定时测速只在窗口开着时工作，关掉程序就自动失效。

🚀 第一次用：照这 3 步闭眼跑通

1

把节点拉进名单

打开工作台，点订阅区右上角的 刷新，勾上你想测的订阅（会默认全选里面的节点）。

节点太多怕费流量？用表格上方的 搜索 或输入“前 10”点 勾选，只留下要测的。

2

选最省心的“两段优选”

新手别纠结参数，直接点顶栏的 智能两段优选（确认弹窗会告诉你大概耗多少流量）。

它会先用 1 MiB 给所有人摸底海选，再挑出前 10 名用 20 MiB 认真复测一遍。

3

看榜换线，不满意可退

跑完后，左上角黑卡 “最佳路由” 会亮出第一名。

先在底栏点 刷新策略组 选好要改的组，再点 切换最优。想反悔点 切回原节点 即可。

🧭 界面上这么多按钮，分别什么意思？

怕点错扣流量或切乱网络？看下面这三类标记就够了：

按钮 / 选项 动作性质 5 岁小孩也能懂的解释
刷新 / 刷新策略组 零流量 只看一眼你电脑里 Clash Verge 现在有哪些订阅和策略组，不会联网测速。
开始测速 消耗流量 按下面参数条选好的“并发数 / 每节点多少 MiB / 模式”，对所有打勾的节点跑一遍。
智能两段优选 消耗流量 最推荐：先派 10 个兵用 1 MiB 粗测，再挑前 N 名（最多 10 个）用 20 MiB 精测，省流量又准。
加压验证 · 20M 较耗流量 严考模式：对每一个打勾的节点都下载 20 MiB（2 个节点并行、4 条线程）。节点多时小心流量！
并发 与 模式(快速/精确) 参数设定 并发 = 同时派几个人出去跑；快速(2流)/精确(4流) = 每个人同时用几根吸管喝水。注意：同时喝水的吸管总数 = 并发 × 流数，开太大节点会互相抢带宽，测不准！
启用定时 周期耗流量 软件开着的时候每隔 N 分钟自动跑一次。如果同时打开了“自动切换最高分”，每轮跑完会自己帮你换最快节点。
切换最优 / 切换选中节点 改动策略组 把底栏选中的 Clash 策略组切到指定节点。不会自己换订阅；想恢复原样点旁边的 切回原节点。
表格行 右键菜单 快捷操作 在某一行节点上点鼠标右键（或按 Shift+F10），可以单独对这一个节点「复测 20M」「直接切换」或「复制名字」。

💻 Windows 版和 macOS 版有什么不一样？

能直接做到的

  • 同时加载最多 32 个订阅、2000 个节点做横向对比。
  • 通过本机安全管道（Named Pipe 或 AF_UNIX）读取和切换当前正在使用的那份订阅里的策略组。
  • 支持 切回原节点（针对刚刚确认成功的直接切换）。

跨订阅第一名时的操作（重要）

Windows 版不会偷偷替你换 Clash Verge 里的订阅。

如果最高分来自另一个订阅：请先打开 Clash Verge 手动切到那份订阅 → 回到助手点 刷新 和 刷新策略组 → 再点底栏亮起来的 继续应用最优。

macOS 专属能力

  • 运行时桥接：授予辅助功能权限后，可直接调起官方 Clash Verge 的内部接口，最高分在其他订阅时能尝试自动帮你跨订阅切换并应用。
  • 仅修改运行时内存，不改动官方 Clash Verge.app 文件或签名。

macOS 版注意事项

  • 当前构建面向 Apple Silicon（arm64）macOS 12+，使用本地 ad-hoc 签名。
  • 自动切换通过本机唯一确定的 Unix socket 进行，不需要把外部控制器开到公网。

🛟 遇到这几个状况先别慌（人话排错）

1. 刷新后找不到某个订阅，或整次刷新失败？

原因：为了不触发隐藏联网或读错配置，助手只认老老实实把节点写在 proxies 列表里的配置。

怎么办：如果订阅里用了 proxy-providers、rule-providers、重名节点或特殊别名，请先在订阅侧转成展开的普通 YAML 再刷新。

2. 提示“切换结果未知”且切换按钮全变灰锁死？

原因：切换指令发出去了，但没等到确定回执（可能成功了也可能中途断了）。助手为了防止你连点把网络切乱，主动把切换功能锁住。

怎么办：千万别反复重试，直接打开 Clash Verge 看一眼当前策略组到底在哪个节点上。

3. 为什么测出来的速度和我平时看视频体感不一致？

原因：一是因为开了 TUN 模式可能让测速流量被二次路由；二是因为只测了连到 Cloudflare 的下载，不代表所有网站（或上传）一样快；三是并发太高互相抢网。

怎么办：想测准一点，可暂时手动关掉 Clash TUN、把并发设为 1、模式选 精确 再重测。

4. 切节点后发现原来“自动选择/测速组”没了？

原因：助手切的是具体某个节点名字。如果策略组原本选的是“自动选择”子策略组，切换后会变成固定节点。

怎么办：点 切回原节点（Windows），或直接在 Clash Verge 里把策略组手动点回原来的“自动选择”即可。

🔧 进阶原理与硬性安全边界（按需展开）

综合分（0–100）到底是怎么算出来的？

只有同时满足“完成 6 次 HTTP HEAD 请求且至少 3 次拿到 2xx 响应 + 下载正文完整达到目标字节数”，节点才算有效并参与算分。公式如下（S=MiB/s，L=延迟 ms，F=HEAD 失败率 %，J=抖动 ms）：

综合分 = 40 × min(1, ln(1 + S) / ln(26))   # 速度权重 40 分（25 MiB/s 拿满）
       + 30 × clamp(1 - L / 500, 0, 1)      # 延迟权重 30 分（500 ms 及以上归 0）
       + 20 × clamp(1 - F / 100, 0, 1)      # 稳定性权重 20 分（6 次 HEAD 成功率）
       + 10 × clamp(1 - J / 100, 0, 1)      # 抖动权重 10 分（100 ms 及以上归 0）
流量估算、非原子切换与隐私边界
  • 流量不是硬上限：界面显示的预计 MiB 只算“节点数 × 单节点下载目标字节数”，不含 6 次 HEAD 探测、TLS 握手、重传或代理协议额外开销；若服务器/节点异常，实际流量可能明显更高。
  • 非原子切换风险：写前/写后会核对配置快照、控制器身份和策略组当前选择，但本质上不是原子 CAS 操作，其他客户端同时改动仍可能覆盖结果；请以 Clash Verge 界面最终状态为准。
  • 本地隐私：测速时节点名称会作为过滤参数传给本机 clash-speedtest 子进程命令行（本机有权限查看进程列表的程序可见）；分享截图或导出的 TSV 前注意脱敏。
