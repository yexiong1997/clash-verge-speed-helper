# macOS 多订阅测速助手使用指南

> **验证范围。** 当前脚本标记应用为 **0.1.0（build 1）**，构建目标为 **Apple Silicon（arm64）、macOS 12 或更新版本**；编译目标不代表已在所有 macOS 版本上运行验证。开发验证使用合成订阅、节点和本地模拟控制器；开发者没有使用真实节点测速、切换真实订阅或向真实控制器写入。测试覆盖的场景不代表所有环境都可用，请以具体构建和发布说明为准。
>
> 当前 worker 不支持 SSH、WireGuard 节点或使用自定义 `headers` 的 HTTP 节点；具体限制见 [worker 契约](../Worker/CONTRACT.md)。应用不是不可信订阅的网络沙箱，不保证阻止对局域网或其他内部地址的连接；请仅在信任订阅、了解流量费用及切换风险后使用。

## 它做什么、不做什么

这是一个独立的多订阅测速应用，不是对已有 Clash Verge 应用的升级。它读取本机 Clash Verge 已登记的订阅列表，允许直接在测速列表中勾选不同订阅的节点，测速后按综合分排序。**点击“开始测速”、加压测试或启用定时即表示同意相应操作，不再出现二次确认。** 测速会连接真实节点和外部服务并消耗流量；启动应用、刷新或勾选列表本身不会开始测速。

自动应用最高分是**默认关闭、可选的功能**。最高分来自其他订阅时，助手会通过已连接的官方运行时补丁调用 Verge 自己的 `patch_profiles_config`，切换成功后自动重新读取订阅列表、策略组和界面状态并继续应用；注入不可用或结果无法确认时会停止并明确提示，不会用当前订阅的第二名替代。界面不再提供“先手动切换订阅再应用”的继续按钮。

## 界面与动效

当前采用 [A 石墨安静版](SCHEME_A_GRAPHITE.md)，保留原有工作台布局。深色模式使用不透明石墨色卡片、雾蓝强调色和单层边框，浅色模式使用同一组语义颜色。测速期间保持列表行序，阶段完成后按综合分排序；最高分卡片仍实时更新。底部进度条使用 450 ms 的单次过渡，卡片结果反馈在 300 ms 内结束。系统「减少动态效果」开启后直接显示最终数值与进度。

## 构建、签名与安装

### 先准备一个隔离构建目录

需要 Apple Silicon Mac、macOS 12 或更新版本、可用的 Xcode/Command Line Tools 与 macOS SDK、网络和足够磁盘空间。脚本会从公开来源下载固定版本的 Go 1.25.0、上游源码和 Go 模块，并进行脚本规定的校验；默认模块镜像为 `https://goproxy.cn`，也可依照构建脚本选择 `https://proxy.golang.org`。构建流量与稍后的测速流量是两回事。请先检查并信任源码和脚本。

**等所有协作者停止修改相关输入后再复制、构建。** 构建脚本会检查它所读取的副本在构建期间是否变化，但不能证明复制多个正在编辑的源文件时得到的是同一时刻的一致快照。确认工作树稳定，或使用您自行核验的稳定源码快照。

下面的示例从项目根目录执行，仅复制明确列出的构建输入到 `/private/tmp` 下新建的私有目录，再在那里构建；不要在 iCloud Drive、桌面/文稿云同步目录或其他 File Provider 管理的位置构建。`/private/tmp` 应是本机实际目录、不是受 File Provider 管理或被重定向的目录。脚本只接受路径各级均非符号链接、输出父目录由当前用户拥有且不可被组或其他人写入的新 `.app` 目标；不要用可能是符号链接的 `/tmp` 作为输出路径。

```bash
(
  set -eu
  umask 077
  PROJECT="$(pwd -P)"
  WORK="$(/usr/bin/mktemp -d /private/tmp/clash-multi.XXXXXXXX)"
  printf '私有工作目录：%s\n' "$WORK"
  /bin/mkdir "$WORK/src" "$WORK/output"
  /bin/mkdir "$WORK/src/Sources" "$WORK/src/Worker" "$WORK/src/Scripts"

  for file in MultiMain.swift ProfileRegistry.swift MultiBatchRunner.swift \
              VerifiedMeasurement.swift CompositeScore.swift TestSchedule.swift \
              SwitchController.swift AssistedSwitch.swift ClashRuntimeInjector.swift; do
    /bin/cp -X "$PROJECT/Sources/$file" "$WORK/src/Sources/$file"
  done
  for file in verified-worker.patch UPSTREAM-GPL-3.0.txt NOTICE.md CONTRACT.md; do
    /bin/cp -X "$PROJECT/Worker/$file" "$WORK/src/Worker/$file"
  done
  for file in build-multi.sh build-verified-worker.sh; do
    /bin/cp -X "$PROJECT/Scripts/$file" "$WORK/src/Scripts/$file"
  done

  /bin/bash "$WORK/src/Scripts/build-multi.sh" \
    --output "$WORK/output/Clash 多订阅测速助手.app"
  /usr/bin/codesign --verify --deep --strict \
    "$WORK/output/Clash 多订阅测速助手.app"
  printf '构建完成，应用位于：%s\n' "$WORK/output/Clash 多订阅测速助手.app"
)
```

这是构建示例，不会由脚本安装、打开应用或对节点测速。构建失败时，脚本会保留它新建的不完整输出以供检查，不要运行不完整的应用。重试可另建一个全新的私有工作目录；不要为解决错误而删除或覆盖其他应用、其他人的文件或未知路径。

如已经拥有完整、可信的固定版本构建缓存，也可选择离线重建 worker；这不是把旧 worker 二进制直接装入应用。缓存必须是绝对的物理目录，包含固定的 `upstream.tar.gz`、对应系统和架构的 `go1.25.0.<os>-<arch>.tar.gz` 及 `modcache/cache/download` 中所需模块文件。脚本会检查缓存与构建目录的所有权、权限和路径，重新校验归档和上游 `go.sum`，并在新的私有目录编译；它不会沿用旧的 worker、提取后的模块或 Go 编译缓存。离线方式不会联网获取 Go 发布元数据，而是使用脚本中固定的 Go 摘要；缓存不完整或不安全时会失败。将上例括号内的构建命令替换为下列形式，并自行填入可信缓存的绝对路径：

```bash
env VERIFIED_WORKER_OFFLINE_CACHE="/绝对路径/可信缓存" \
  /bin/bash "$WORK/src/Scripts/build-multi.sh" \
    --output "$WORK/output/Clash 多订阅测速助手.app"
```

`VERIFIED_WORKER_OFFLINE_CACHE` 一旦设置即启用离线模式，空值也不会回退到联网构建。离线构建只针对构建过程；它不限制您之后确认测速时的联网行为。

### 安装并清理旧版本

如果要使用当前用户的标准安装位置，直接运行项目提供的安装脚本：

```bash
/bin/bash Scripts/install-multi.sh
```

脚本先在 `/private/tmp` 构建并核验新包，再清理本项目的旧助手、Direct/Patched 构建包和临时验收包，最后安装到 `~/Applications/Clash 多订阅测速助手.app` 并再次核验。默认检查 `/Applications`、`~/Applications`、本项目 `build/`、`~/Documents/Codex`、废纸篓和 `/private/tmp` 中本项目命名前缀的构建/验收目录。仅目录名相似不足以删除：完整 App 必须匹配本项目的 Bundle ID；与原版同 Bundle ID 的实验包还必须位于生成位置且为 ad-hoc 签名。官方原版、正式助手和此次构建的新包受到保护。

编译失败时还可能留下没有 `Info.plist` 的同名 `.app` 目录，常规应用搜索不会列出它。清理器会检查 `clash-multi.` 等本项目临时目录前缀，并只在目录名、缺失的 plist 和 `.build-multi-work` 构建标记全部符合时清理这种残留；正在编译的输出会保留。

清理器还会逐条注销已删除包及失效的本项目应用注册，不重置其他应用的图标布局。遇到正在运行的旧实验包时，清理会停止，不会强行结束它。安装过程中若正式助手仍在运行，安装脚本会先请求它退出，无法退出就保留旧安装并失败。安装暂存包退出清理时会注销，避免再次留下临时图标。以后更新也使用此安装脚本。

替换正式助手前，安装脚本先检查其现有系统登记，并在旧包仍存在时注销；注销失败会保留旧包并停止安装。没有登记的不完整安装可以直接替换。新包复制并通过签名核验后，脚本只重新导入该 App 的 Spotlight 元数据，再登记安装路径；不会重建整盘索引或重置启动器布局。

需要先检查清理范围时运行：

```bash
Scripts/prune-clash-apps.sh --dry-run
```

如需隔离验证，设置由当前用户拥有的冒号分隔根目录：

```bash
CLASH_LEGACY_CLEANUP_ROOTS="/private/tmp/my-clash-artifacts" \
  Scripts/prune-clash-apps.sh --dry-run
```

如需在隔离目录中验证清理逻辑，可设置一个由当前用户拥有的临时目录：

```bash
CLASH_MULTI_INSTALL_ROOT="/private/tmp/my-clash-apps" \
CLASH_LEGACY_CLEANUP_ROOTS="/private/tmp/my-clash-apps" \
  /bin/bash Scripts/install-multi.sh
```

此构建使用本机 **ad-hoc 签名**，没有 Developer ID 签名，也没有 Apple 公证。macOS 可能阻止首次打开；只有在您确认来源可信并接受风险时，才使用系统提供的针对该应用的允许打开流程。不要全局关闭 Gatekeeper，也不要用管理员权限覆盖现有应用。

## 选择订阅与节点

1. 在本机的 Clash Verge 中准备好要测的已登记订阅，然后打开这个独立助手。点击 **“刷新订阅”** 获取列表。
2. 列表可显示 Verge 登记的远程或本地订阅；它读取的是本机登记内容的快照，不是一个任意 YAML 文件选择器。勾选一个或多个订阅，核对显示的名称、UID 和当前订阅标记。**能在列表中勾选，不等于该订阅一定能通过测速前检查。**
3. 勾选订阅后，主窗口中间的**节点实时遥测队列**会加载节点，默认全部勾选；直接点每行左侧的复选框决定哪些节点参与测速。可按订阅名、UID 或节点名搜索，并对当前搜索结果使用 **“全选当前”**、**“清空勾选”** 或输入数量 `N`（1–2000）点击 **“选前 N 项”**（仅勾选当前列表显示顺序中的前 `N` 个节点，其余取消勾选）。至少勾选一个节点才能启动测速；不同订阅的同名节点分别选择。
4. 测速列表显示已选数量和估计流量。刷新或改变订阅选择会重新加载列表并默认全选；如果订阅快照变化，开始前的检查会拒绝继续。修改节点勾选会停止已启用的定时任务，需重新启用。搜索只筛选显示，不会自动更改未显示节点的勾选。
5. 此版本只接受配置中直接内联、非空的 `proxies` 列表及合法节点名称。含 `proxy-providers` 或 `rule-providers` 的配置会被拒绝，**即使对应内容为空也不支持**；YAML 别名、显式标签、重复键、多个文档或非字符串映射键也不支持。请先在 Verge/订阅来源侧准备符合条件的配置，不要绕过校验。
6. 结果身份以**订阅 UID 的 UTF-8 字节 + 节点名的 UTF-8 字节**区分：不同订阅的同名节点可分别显示，同一订阅内重复节点名会被拒绝。同名也不证明运行时实际端点相同。
7. 当前检查上限为 32 个订阅、总计 2000 个节点、单个配置 1 MiB、唯一快照合计 8 MiB，另有 64 MiB 的按实际待测节点复制快照预算。超过上限或快照在检查期间变化时，可能无法开始；缩小选择范围、确认配置后再试。
8. 排队节点启动前会在后台依次核对订阅快照；每次核对从实际开始时计时，若发现变化或约 15 秒内未能向主线程交付结果，会停止后续节点及定时。普通排队时间不计入该次检查时限。停止操作不会强制中断已经卡住的系统文件调用；如果先前读取仍被系统阻塞，新的核对也可能等待约 15 秒后超时，请排查存储并重启助手。初始读取、应用文件检查等其他阶段也可能受无响应磁盘影响，停止或退出不保证立即完成。核对与启动之间仍不是原子操作。

名称中含“剩余流量”“到期”“流量重置”“订阅信息”等典型信息项可能仍然显示或被处理，但不参加自动最高分排名。这只是基于名称的保守过滤，不能识别所有信息项；手动选择不会替您判断节点是否可用。不要在订阅名或节点名中放入凭据、令牌、地址等敏感内容。

## 测速：流量、并行与精度

1. 选择**全局并行 1–10**，这是所有已选订阅合计可同时测速的**节点数上限**，默认 **10**，并非每个订阅各自 10 个。
2. 选择每节点目标下载数据量，全部八档为 **256 KiB、512 KiB、1 MiB、2 MiB、3 MiB、5 MiB、20 MiB、50 MiB**，默认 3 MiB。
3. 模式默认 **“快速 (2 流)”**；也可选 **“精确 (4 流)”**。当前默认的每节点请求超时 / HEAD 延迟上限为：快速 `3s / 1s`，精确 `3s / 2s`。下载流数是**每个正在测速的节点内部**并行下载的流数，与上面的节点并行上限是不同的两项。例如并行节点数为 4、精确模式为 4 条流时，可能有多达 16 条下载流并行竞争同一条网络连接。精确模式不会自动把节点并行设为 1。
4. 开始前先核对列表勾选、显示的总流量、并行数、模式和自动切换开关。若启用自动应用且选中的节点包含当前订阅，先在底部悬浮控制岛选好当前订阅的 `Selector` 策略组；当前组及其当前选择会显示在界面上。随后点击右上角工具栏的 **“▶ 开始测速”**，检查通过后就会联网，**没有二次确认**。只选其他订阅时，最高分仍须您手动切换订阅后才能申请应用。
5. 点击右上角工具栏的 **“⚡ 加压验证 · 20M”** 会立即设为**全局最多 2 个节点并行、精确模式（每节点 4 条下载流）、每个勾选节点 20 MiB**，停止已有定时授权并开始普通测速检查，**不会再弹确认框**。它不是只测试两个节点；勾选多少就会安排多少。自动应用开关沿用当前状态，请点击前特别核对。这个预设仍会产生带宽竞争，不保证是最大吞吐或最准确的结果。

界面显示的目标下载量大致是 `节点数 × 每节点所选数据量`。例如 10 个节点各选 3 MiB，目标下载正文约为 30 MiB，另有 HEAD 等请求；中断或失败也可能已经产生流量。这里衡量的是下载**正文的实际读取字节**，不是包含所有请求、连接、重传、代理开销或计费规则的流量硬上限，账单可能不同。勿在严格流量预算或按量计费网络中把这个估算当成封顶承诺。

同时测多个节点会争抢家庭网络、Wi-Fi、CPU 和远端服务，排名可能随时间波动。若更重视可比性而不是速度，建议手动把节点并行数设为 **1**，选择精确模式，避免其他大流量任务，并在相近条件下多次测量；这仍不能消除网络波动，也不保证精确模式一定更准确。

## 手动切换选中的节点

无需先测速：先勾选目标订阅，在主窗口的测速列表中**点选目标节点行**，在底部悬浮控制岛选择当前订阅的 `Selector` 策略组，核对界面显示的组和当前选择，然后点击右下角底栏的 **“⚡ 切换至选中节点”**。点击即申请切换，**不再二次确认**。复选框决定待测节点，行高亮决定手动切换目标，两者用途不同；未勾选、未测速或测速失败的节点也可主动选择，请自行确认其可用性。

如目标属于其他订阅，点击 **“切换至选中节点”** 时，助手会先尝试通过运行时补丁切换订阅并刷新界面，然后自动继续申请策略组切换。若桥接不可用，操作会停止并明确提示，不再显示“手动切换后继续”的按钮。快照变化、无法验证或目标不是该组直接成员时不会发起切换；结果未知时不要盲目重试。发起切换会停止已启用的定时任务。所有检查与写入仍非原子操作，切换后应在 Verge 核实。

## 理解综合分

当前设计要求每个有效结果完成 **6 次 HTTP HEAD，至少 3 次成功**，且下载完整、实际字节数与预期相符，速度和延迟为正的有限数，抖动为非负有限数；否则不计算有效综合分。成功 HEAD 指未跟随重定向的 2xx 响应。HEAD 延迟是成功请求的平均值，HEAD 抖动是成功请求延迟的总体标准差，HEAD 失败率为 `(6 - 成功次数) / 6 × 100%`。这是 HTTP 请求失败率，**不是网络丢包率**。worker 的具体协议、安全及边界行为请参见[worker 契约](../Worker/CONTRACT.md)。

令 `S` 为 MiB/s、`L` 为毫秒、`F` 为 HEAD 失败率百分数、`J` 为毫秒，`clamp(x, 0, 1)` 表示将值限制在 0 到 1 之间；合格结果的当前公式是：

```text
综合分 = 40 × min(1, ln(1 + S) / ln(26))
       + 30 × clamp(1 - L / 500, 0, 1)
       + 20 × clamp(1 - F / 100, 0, 1)
       + 10 × clamp(1 - J / 100, 0, 1)
```

总分为 0–100，速度部分在 25 MiB/s 达到满分；延迟、失败率和抖动分别影响其他部分。分数是本次到指定目标的综合指标，不是未来表现、所有网站体验或安全性的保证。无效、未完成或信息项不应当作可切换的最高分节点。

## 外部控制器与订阅切换

当前实现使用可唯一确定的、属于当前用户的本机 Unix 控制器，查询并切换当前内核中的 `Selector`；不需要为了本助手另外启用 TCP 外部控制器，也不在助手中输入 TCP API 密钥。请不要为了此功能将控制器开放到公网或降低认证保护。

就已查阅的官方源码而言，Mihomo 的配置接口用于重载或替换**内核配置**，而 Verge 的订阅激活由应用内部的配置流程管理，二者不能安全地直接等同。本助手通过官方页面内的运行时补丁调用 Verge 自己的订阅事务，不直接改内核配置；补丁不可用时会停止，不模拟订阅切换。不同版本的接口可能变化，不能据此断言所有第三方工具或未来版本都没有其他方式。参考 [Mihomo 配置路由](https://github.com/MetaCubeX/mihomo/blob/Meta/hub/route/configs.go) 和 [Verge 订阅配置命令](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src-tauri/src/cmd/profile.rs)。

## 可选的应用最高分与撤销

### 最高分属于当前订阅

1. 如需启用，勾选 **“测速后自动应用总体最高分（仅当前订阅）”**；默认未勾选。确保 Verge 当前订阅也被选中，且您愿意改变策略组的当前选择。
2. **点击开始之前**，在列表下方选择当前订阅的 `Selector` 策略组，并核对显示的当前选择。只有一个可用且非 `GLOBAL` 的组时，界面可能默认选中；存在多个候选或仅有 `GLOBAL` 时须由您明确选择。点击 **“开始测速”** 即开始检查并可能测速和切换，不会再弹确认。选择不完整覆盖的组时，最高分不在其中就不会切换。
3. 测速及必要校验完成后，仅当**总体最高分**属于当前订阅、是该组直接成员且相关检查通过时，才可能应用。没有可用最高分、环境或策略组检查失败、组里没有最高分等情况下不会拿次优节点代替。

### 最高分属于其他订阅

只有启用自动应用时，最高分属于其他订阅才会进入后续流程，并停止定时等待当前流程完成；助手会先通过运行时补丁切到提示的目标，再刷新策略组和界面并自动继续应用。若注入不可用，操作会停止并提示检查桥接。助手会重新检查目标订阅、快照、控制器和策略组；若不匹配或校验失败不会继续，也不会改选第二名。存在多个策略组且没有选择时，会提示先在主界面选择当前订阅的策略组；选择后会继续自动应用。修改选项、重新选择或刷新订阅可能清除待处理的最高分。

应用前后会检查订阅、控制器和策略组状态，但**检查与控制器 PUT 不是原子操作**，其他用户操作、配置更新或控制器客户端仍可能同时改变状态；同名节点也不证明运行端点身份。固定到具体节点可能取代原本的自动选择策略，已有连接可能继续使用旧选择，Verge 异步恢复订阅或策略时也可能在复核成功后再次覆盖选择。请回到 Verge 检查实际结果，必要时在 Verge 手动恢复原策略、原节点或原订阅；助手不会替您自动撤销。

若显示**切换结果未知**，请求可能已经发生：先在 Verge 核对实际状态，**不要盲目重试**，再由您手动处理。

### 停止正在进行的操作

点击 **“停止”** 可请求停止当前工作、取消尚在排队的测速并撤销定时授权；等待状态更新后再关闭窗口。撤销只能阻止**尚未通过最终授权检查**的切换；已经通过检查但尚未发送的请求仍可能在点击停止后发出，已经发送或正在处理的请求也不能撤回。因此不能保证撤销已经生效的切换或已消耗的流量。切换正在进行时应等待结果，并在 Verge 核实；关闭忙碌窗口时也需要先停止并等待。仅想停止未来的周期运行时，请用 **“停止定时”**，再按需要停止当前测速。

## 可选的应用内定时测速

默认未启用。可选间隔为 **15 分钟、30 分钟、1 小时、2 小时、6 小时、12 小时、24 小时**。启用前请先确认所选订阅、每节点数据量、节点并行和模式；如不想每次可能切换策略组，保持自动应用关闭。

1. 先核对节点、单次估计流量、间隔和自动切换开关；若启用自动应用且选中范围包含当前订阅，先在主窗口选好策略组。**每轮都会重新联网并消耗流量**。开启自动应用即持续授权该策略组：每轮会以当时的当前节点为基线，符合条件时可能**覆盖您在两轮之间手动选择的节点**。不希望这样时，应关闭自动应用或停止定时。
2. 点击 **“启用定时”** 即授权周期测试和已显示的自动切换选项，**没有二次确认**。首次运行在启用后一个间隔，而不是立即运行。
3. 要撤销，点击 **“停止定时”**；停止之后不会安排新的定时轮次，并会尝试取消正在运行的定时测速。已通过最后取消检查的进程启动仍可能发生；正在手动进行的测速不因停止定时而自动取消，必要时再点 **“停止”**。已有切换正在运行时请检查状态并在 Verge 核实：已通过最终授权检查的切换即使尚未发送也可能随后发出，已发出的请求无法撤回。

定时器只在应用运行期间工作，不是系统级后台任务：关闭应用会停止，重启后默认不重新启用，必须再次明确同意。睡眠、唤醒、系统繁忙和应用退出都不保证准时运行；到期时若忙碌或正在刷新策略组会跳过，不积压、不补跑。一次运行结束后按后续间隔重新安排，界面轮询也可能有延迟。修改设置、选择或刷新订阅会停止定时；配置变化、全部节点无合格结果、系统性错误，或启用自动应用时最高分属于其他订阅等情况也可能使定时停止，需检查状态并在需要时重新授权。自动切换后的策略组刷新若失败、超时或无法确认原授权目标，也会停止定时，不会静默改选其他策略组。单个节点失败本身不会让其他合格结果失效。不要依赖它作为可靠的后台或精确计时器。

## 隐私与联网提醒

- 每次点击开始测速、加压测试或到达已启用的定时时间后，应用会对勾选节点发起真实连接，默认测速目标为 `https://speed.cloudflare.com`。订阅里的节点服务器及其依赖（例如名称解析或其他配置指定端点）也可能产生外部连接；**不支持 provider 不等于不会访问其他端点**。请自行确认您信任这些目的地及其费用。
- 订阅配置作为输入快照提供给 worker，而节点名形成的过滤参数可能出现在子进程命令行中；本机有权限查看进程参数的人可能看到相关名称。不要在名称里放秘密，也不要把此实现视为隔离不可信订阅的沙箱。
- **“复制结果”** 会把订阅名称、UID、节点名称及测量结果放到系统剪贴板。为降低粘贴到表格时的公式注入风险，潜在公式前缀会转义，表格分隔符会替换，因此复制内容可能与原始名称不完全一致；这不是对所有表格软件行为的保证。发送截图、日志或粘贴内容前先检查并脱敏；剪贴板同步或其他有权限的软件也可能接触这些内容。不要公开凭据、订阅地址或真实节点信息。
- 结果反映当前订阅快照、网络环境及当时的测速目标，不代表随后订阅更新后的节点状态。需要切换时，请重新核对 Verge 中的实际配置和策略。
