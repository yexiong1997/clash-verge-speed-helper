# Clash 节点测速助手

一个面向 macOS 的本地桌面助手：读取 Clash Verge Rev 当前配置或用户选定的 YAML，用 [faceair/clash-speedtest](https://github.com/faceair/clash-speedtest) 逐节点进行**真实下载测速**，展示并复制结果；也可在用户确认后，将指定 Clash 策略组切到测速最快的合格直接成员。启动时会尝试向已安装的官方 Clash Verge Rev 注入运行时桥接，不修改 `.app`、不重新签名、不重装。

> 本页主要描述原来的单订阅版本。独立的多订阅版本（V4 Clear Prism Glass 透明底毛玻璃胶囊界面 + 全量交互动效）支持跨订阅直接勾选节点、一键选择当前列表前 N 项节点、智能两段式漏斗优选（快速初筛自动晋级前 N 名进行 20 MiB 加压复测）、实时动态榜单重排、内联吞吐能量条与延迟分级胶囊、表头点击排序与状态筛选、最优路由卡片一键直切/单节点复测、双击行/右键菜单操作、跨订阅切换就绪自动感知、一键安全切回原节点及应用内定时实时倒计时；其开关默认值、测速组件和切换流程不同。多订阅版本启动时会尝试自动注入官方 Clash Verge 的运行时补丁，具体状态以窗口底部提示为准。请阅读[多订阅版本使用指南](docs/MULTI_SUBSCRIPTION.md)，并以该版本的构建与验证状态为准。

> **开始前请注意（以下为原单订阅版本）**
>
> - 测速会连接真实节点和 Cloudflare 并消耗流量，可能计入订阅额度或产生费用；显示的流量是估计值，**不是上限**。
> - “测速后自动切换最快节点”默认勾选。它会改变所选策略组的当前选择；只想测速，请先取消勾选。
> - 自动切换包含多次检查，但并非原子操作，也不能保证完全安全。不要在关键业务、不可容忍切换或流量消耗的环境中贸然使用。
> - 本项目的许可证尚未指定；公开查看不自动授予一般性的使用、修改和再分发权限（GitHub 服务条款可能允许查看和 fork）。上游组件的许可另见[第三方说明](docs/THIRD_PARTY.md)。

## 环境与构建

当前构建设计面向 **macOS Apple Silicon（arm64）**。需要 Xcode Command Line Tools（包括 `swiftc`）、系统 AppKit、`/usr/bin/ruby`（带 YAML/JSON 支持）、`/usr/bin/curl`；运行本地测试另需 Python 3，端到端测试还需要 `/usr/bin/sandbox-exec`。自动切换需要正在运行、配置和本机 Unix 控制接口可被当前用户访问的 Clash Verge Rev / 兼容内核；仅测速不要求它正在运行。

### 官方 Clash Verge 运行时桥接

助手启动时会校验 `/Applications/Clash Verge.app` 的 Bundle ID、Developer ID Team ID 和代码签名，然后按需启动官方 App，显示主窗口并打开官方 Web Inspector。它通过辅助功能权限向 Console 输入一次短加载器；加载器在官方 `tauri://localhost` 页面内调用原版 `patch_profiles_config`，再由助手本地回环桥接发送已验证的命令。

该流程只修改运行时内存，不写入 Clash Verge `.app`，不重新签名，也不安装登录项。首次运行需要在“系统设置 → 隐私与安全性 → 辅助功能”授予本助手权限；缺少权限、找不到官方包或签名不匹配时，窗口会明确显示失败原因，测速仍可继续使用。退出助手会关闭桥接，不退出 Clash Verge。刷新或重建 WebView 后，下一次启动助手会重新注入。

多订阅版本的构建与安装使用 [`Scripts/install-multi.sh`](Scripts/install-multi.sh)。它先构建并核验新包，再清理 `~/Applications` 中本助手的旧副本、运行时副本和备份，最后安装唯一的 `Clash 多订阅测速助手.app`；不会清理官方 Clash Verge 或其他应用。

在项目根目录执行：

```sh
./Scripts/build.sh && open "build/Clash 节点测速助手.app"
```

默认构建通过 [`Scripts/fetch-worker.sh`](Scripts/fetch-worker.sh) 获取固定版本的上游 `clash-speedtest` v1.8.6 Darwin arm64 官方归档并验证 SHA-256，再将组件放入 App；首次获取需要访问 GitHub。也可先单独执行 `./Scripts/fetch-worker.sh`。源码仓库不提交下载的依赖二进制。上游下载位置、散列和许可注意事项见[第三方说明](docs/THIRD_PARTY.md)。如果下载失败或校验不符，请停止构建并检查网络、来源和脚本，**不要绕过校验**。

应用包标记为 **0.1.0（构建号 1）**，编译目标和最低系统版本标记为 macOS **12.0**；这些是构建设置，不代表已验证所有 macOS 版本或机型，也不承诺 Intel Mac 可用。构建使用本机临时签名（ad-hoc），不是 Apple Developer ID 签名，未公证。首次打开如遇系统安全提示，先核实文件来源和构建方式，按本机安全政策处理；不要为运行它而全局关闭系统防护。

如果签名报 `resource fork, Finder information, or similar detritus not allowed`，某些 Finder / File Provider 环境可能正在为新生成的 App 添加 `com.apple.FinderInfo`。脚本只尝试清理输出根目录上的这一属性，但后台重新添加仍可能令签名或后续校验失败。请将完整源码放到**不由云同步或 File Provider 管理的本地目录**再构建；检查失败时留下的未完成 App 后再自行清理，不要全局关闭安全防护。

## 使用

1. 打开 App。它会尝试查找 Clash Verge Rev 当前订阅；也可以选择其他本地 `.yaml` / `.yml`。启动时可能读取本地配置并通过本机控制接口**查询**策略组，但不会在用户确认前启动测速或发出切换请求。
2. 查看节点数和估计流量，选择模式和每节点下载目标。若只想看结果，**取消勾选自动切换**。如需自动切换，确保使用当前订阅，点击“刷新策略组”，选好明确的 `Selector` 策略组；只有唯一一个非 `GLOBAL` 组包含全部待测节点名称时，界面才会建议选中它，仍请自行核对。
3. 点击“开始测速”，阅读配置、流量和是否切换的确认框；确认后才开始。表格显示节点名称、类型、延迟、抖动、请求失败率和下载速度，按有效下载速度降序排列。“复制结果”会把节点名称一并放到系统剪贴板。
4. 需要中止时点击“停止”。停止会终止进行中的测速进程、不再启动待测节点，并保留已经处理的结果；本轮不会自动切换。切换前核对和最终切换/验证阶段需等待完成，不能把“停止”当成已经发出切换请求后的撤销。

### 快速与精确模式

| 设置 | 快速（初筛） | 精确（复测） |
| --- | --- | --- |
| 节点调度 | 最多同时 4 个节点 | 一次 1 个节点，重新测全部节点 |
| 每个节点的下载并发 | 2 | 4 |
| 传给组件的 `-timeout` / `-max-latency` | `12s` / `2s` | `30s` / `5s` |
| 切换到该模式时的默认目标 | 3 MiB/节点 | 20 MiB/节点 |

两种模式都可选 3、5、20、50 MiB/节点；切换模式会重置为该模式默认值。快速模式的节点会争用本机带宽、超时较短，较慢节点可能被判失败，适合初筛；精确模式逐个测试，通常耗时更长，仍是估算，不保证排序稳定或更符合所有应用场景。需要可靠决策时请在不同时段复测，并同时考虑延迟、稳定性和实际用途，不能只看一次最高下载值。

### 真实测速、流量与误差

助手为每个节点启动一个独立的上游测速进程，按精确节点名称筛选，通过该节点访问 `https://speed.cloudflare.com/__down`。界面上的目标约为**节点数 × 每节点设置的 MiB**；它不包含延迟探测、协议开销或重试等，也不是强制字节上限：服务器、代理或响应异常时实际流量可能远超估计。请先确认套餐余量和网络费用。这里测的是下载表现，不是对上传速度的测试。上游组件可能将中途超时或不完整传输计入速度，因此显示正数不代表完整下载或节点长期可用，自动切换也可能受到影响。

带宽争用、网络拥塞、限速、节点与测速服务器之间的路径、服务器响应、超时以及节点自身策略等都会影响结果；高下载速度不代表低延迟。若 Clash 的 TUN 已开启，测速流量可能被再次代理或受路由影响。可根据自己的网络情况**手动暂时关闭 TUN，测速后再手动恢复**；助手不会替用户修改 TUN，也无法保证其检测结果完整。关闭 TUN 可能改变全局联网方式，请先了解影响。

## 自动切换：流程与边界

只在勾选并确认时执行；操作目标是用户选定的一个可选策略组，而不是修改所有流量。具体流程：

1. **发现与选择。** 仅当前 Clash Verge Rev 订阅可自动切换。助手发现当前用户拥有的、可唯一确定的本机 Unix socket，并通过本机接口查询策略组；只列出名称安全、类型为 `Selector` 且至少有一个可作为候选的待测节点为其**直接成员**的组。`GLOBAL` 也可能出现在列表中，但不会被自动建议。组内的节点按 UTF-8 名称精确匹配，不会递归到嵌套组中查找。
2. **开始前确认。** 检查订阅路径和内容快照、socket 身份及用户所选组；确认框说明将改变哪个组。用户同意后再读取该组当前选择，记录当时的选择和直接成员，然后开始测速。当前订阅/控制接口或策略组无法确认时，不开始这一轮自动切换测速。
3. **选取候选。** 全部测速完成且未取消后，按有效、有限且大于零的下载速度排序，从测速开始时该组的直接成员中选最快者。名称含“剩余流量”或“到期”的条目**仍会测速并显示，但不会自动选中**；这只是简单的名称过滤，不能识别所有信息条目或坏节点。其他组的更快节点、嵌套组内成员不一定有资格。
4. **再次核对和写入。** 助手再次确认订阅内容和本机 socket 未变，读取所选组，检查候选仍是直接成员、当前选择仍与测速前记录一致，并在发送前再次检查订阅与 socket。若候选本来就是当前选择，无需写入；否则向本机接口发送一次切换请求，再读取策略组确认结果。正常确认要求写入返回 HTTP 204，且后续读取到目标节点。

**这些检查不是比较并交换（CAS）或事务。** 另一个客户端或用户可能在最后检查之后、写入之前更改选择，也可能发生先变更再变回等无法检测的情况；验证之后也仍可能再次变化。助手没有自动回滚，也不承诺避免覆盖所有并发更改。建议测速期间不要手动改组、切换订阅或重启/更换内核，使用完到 Clash 中复核。

自动切换选择的是具体的直接节点：如果原来选的是一个自动测速/自动选择的子策略组，这会把该选择改为固定节点。助手**不会保存或自动恢复**原选择。想恢复时，请在 Clash Verge Rev 的相同策略组中手动选回原来的自动策略/子策略组；事先记下原选项。如没有相应选项，则需按自己的配置在 Clash 中恢复。该操作只影响经过所选策略组的流量，规则、其他策略组和 TUN 可能使部分流量不经过它。

### 无结果、停止或切换结果未知

- 单个节点失败、输出不符合预期、速度为零/非数字等会显示“未完成”或“无有效速度”，不会作为有效速度参与自动选择；全部候选无有效速度时不切换。仅测速模式完成后不执行切换。
- 测速期间点击“停止”会结束该轮并保留已处理结果，不切换。已关闭的窗口或进程无法替代对实际 Clash 状态的核对。
- 发现当前订阅、socket、组的当前选择或目标节点直接成员资格发生不一致，或写入前无法验证时，跳过写入。请检查 Clash 状态，必要时重新选择当前订阅并刷新策略组，再决定是否重新测速。
- **“切换结果无法确认”不等于“未切换”。** 请求可能已被内核执行，但返回状态异常、连接中断或写后读取失败/不一致；助手不会自动重试。请打开 Clash 检查当前组的实际选择，再由用户决定后续操作，不要盲目重复请求。

## 配置范围与已知限制

- 目前只接受本地 YAML 根映射中非空的内联 `proxies` 列表；节点必须都有非空名称，名称不能重复或含控制字符。`proxy-providers` 是非空映射时，即便同时有内联节点，也会拒绝开始测速，以避免由此触发自动联网或缓存写入；其他无效格式并不保证被识别，请自行准备和核查已展开的本地配置。
- 可手选其他 YAML 做纯测速；只有它指向当前 Clash Verge Rev 订阅，且内容快照与当前配置一致时才可自动切换。助手从本机 Clash Verge Rev 的配置目录发现当前订阅和生成配置；无法读取时可手选，但不应因此假设自动切换可用。
- 节点协议与配置项仍受固定版本的上游组件及其内核支持范围约束；本助手不保证所有 Clash/Mihomo 配置、节点类型、复杂引用或第三方客户端均可用。策略组名包含 `/`、`\`、`%`、`?`、`#`、`;` 等不安全路径字符时会被排除；某些名称或输出格式也可能无法处理。
- 自动切换只使用同一用户、路径明确且唯一的 Unix socket；服务模式或生成配置中的多个候选 socket 若同时存在且无法唯一确定，会拒绝猜测。当前 GUI 不提供控制器 secret 输入，也不回退到 TCP；需要 Bearer 认证的接口可能不能使用此功能。不要为此把控制接口暴露到公网或降低现有安全保护。
- 本助手的结果解析依赖固定版本上游的表格格式；组件替换、协议异常或环境差异可能导致“未完成”。不支持上传测速、定时自动测速、自动恢复原策略或跨组递归筛选。

## 隐私与安全

订阅配置、节点地址、凭据、订阅链接、控制接口信息以及节点名称都可能敏感。助手在本机读取所选配置，测速时将配置快照经标准输入传给本地 worker；节点名称会作为筛选参数出现在 worker 的本机进程命令行中，可能被其他本机程序、诊断工具或进程列表看到。助手代码不主动把完整配置或订阅链接作为配置上传服务的请求发送。**这不是零网络或绝对保密的保证**：测速会连接所选节点和测速服务器，DNS、节点服务商、网络运营方以及运行环境中的其他程序可能观察到相应元数据；上游组件及配置自身的行为也应自行审查。

请仅使用可信配置和软件；不要把真实 YAML、订阅地址、节点、密钥、控制器路径、截图、剪贴板内容或未经脱敏的日志提交到公开仓库/工单。结果中含节点名称，复制和分享前请检查。应用将部分 worker 错误隐藏为通用状态以减少意外泄露，但不能保证其他程序、系统日志或崩溃报告不含敏感信息。

## 本地测试

在项目根目录执行以下命令；先获取 worker 再运行端到端测试（下载来自 GitHub，需要网络）：

```sh
python3 -B Tests/test_switch_controller_local.py
./Scripts/fetch-worker.sh
python3 -B Tests/test_helper_e2e_local.py
```

第一个测试用合成数据和临时 Unix socket 检查控制器请求、安全校验、状态变化、确认及结果未知处理。第二个测试使用临时构建的测试 App、合成配置、本地 socket 和回环服务，借助 macOS `sandbox-exec` 限制测试子进程；缺少隔离工具时应拒绝无沙箱运行。它覆盖正常切换、组/配置变化及取消等场景。**获取 worker 是网络下载；测试夹具本身不使用真实节点或真实订阅进行测速。** 测试需要 macOS 开发工具、Python 断言启用（不要用 `-O`）；结果仅说明所测场景，不证明线上完全安全或所有系统兼容。

## 故障排除

| 现象 | 建议 |
| --- | --- |
| 构建失败、组件缺失或 SHA-256 不符 | 确认 Apple Silicon、开发工具及 GitHub 可访问；检查下载脚本和归档来源，重新按脚本获取并验证，不要忽略校验。脚本不覆盖已存在的 App 或有问题的依赖缓存；先自行核对并处理原输出后再试。 |
| 找不到当前订阅 / YAML 无效 | 在 Clash Verge Rev 中确认当前订阅；或手选包含非空内联 `proxies` 的本地 YAML。检查权限、格式、重名/空名/控制字符以及非空 `proxy-providers`。不要公开粘贴配置求助。 |
| 无法发现策略组或提示接口变化 | 确认使用当前订阅、Clash 正在运行，且当前用户只有一个可确定的 Unix 控制接口；检查所需组是名称安全的 `Selector` 且直接包含待测节点，再刷新。仅需测速时取消自动切换。 |
| 节点均失败、速度异常或结果波动 | 检查节点是否可用、Cloudflare 是否可访问和本机网络，确认流量预算；避免其他测速任务占带宽。留意 TUN 和路由影响，可用精确模式及不同时段复测。 |
| 已停止 / 显示未切换 | 查看状态提示和保留结果；检查订阅、组成员、原选择或控制接口是否变化。需要继续时先复核实际 Clash 状态再操作。 |
| 切换结果无法确认 | 可能已经切换；助手不会自动重试。先在 Clash 中查看实际策略组选择，再决定是否手动调整。 |
